# 放到目标项目根目录的两个文件

以下为空白表单，不代表任何项目的已确认事实。填写时删除无用栏目；未知项明确标注。

## PROJECT_CONTEXT.md

- 项目身份：名称、根目录、目标用户、项目目标（区分资料推断和用户确认）。
- 用户长期偏好：只写已明确确认、与本项目有关的偏好。
- 技术和运行：主要技术、实际入口、运行及验证命令（注明是否已执行）。
- 模块索引：职责 → 入口路径 / 关键符号 → 何种任务需要读取。
- 关键约束和已定方案：结论、理由、来源。
- 摘要核验：日期、Git commit（若有）、关联文件及尚未核验的项目。

## CURRENT_TASK.md

- 任务 ID / 状态 / 更新时间。
- 用户原始需求：简明保留边界；标明已确认与待确认。
- 验收标准：用户能观察到的完成结果。
- 当前问题（可选，仅实际出现后填写）：触发条件、预期、实际、影响范围、证据路径。无问题时省略，不作为初始化必答项。
- 已完成：实际改动及验证结果。
- 待验证假设：不要混入事实。
- 下一步：具体入口和动作。
- 工作现场：分支、相关未提交文件、尚未处理的风险或阻塞。

## 项目规则入口

使用本 Skill 目录下的 `scripts/install_project_contract.py` 安装项目根生效规则文件的自动维护受管区块，不手工复制旧版短入口。项目根存在 `AGENTS.override.md` 时写入该文件，否则写入 `AGENTS.md`。脚本只管理标记之间的内容，项目原有规则必须保留；更深层规则仍按其作用域执行。
