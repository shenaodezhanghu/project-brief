# 放到目标项目根目录的两个文件

以下为空白表单，不代表任何项目的已确认事实。填写时删除无用栏目；未知项明确标注。

## PROJECT_CONTEXT.md

- 项目身份：名称、根目录、目标用户、项目目标（区分资料推断和用户确认）。
- 用户长期偏好：只写已明确确认、与本项目有关的偏好。
- 技术和运行：主要技术、实际入口、运行及验证命令（注明是否已执行）。
- 模块索引：职责 → 入口路径 / 关键符号 → 何种任务需要读取。
- 关键约束和已定方案：结论、理由、来源。
- 摘要核验：日期、Git commit（若有）、关联文件及尚未核验的项目。

## CURRENT_TASK.md

- 任务 ID / 状态 / 更新时间。
- 用户原始需求：简明保留边界；标明已确认与待确认。
- 验收标准：用户能观察到的完成结果。
- 当前问题（可选，仅实际出现后填写）：触发条件、预期、实际、影响范围、证据路径。无问题时省略，不作为初始化必答项。
- 已完成：实际改动及验证结果。
- 待验证假设：不要混入事实。
- 下一步：具体入口和动作。
- 工作现场：分支、相关未提交文件、尚未处理的风险或阻塞。

## 可合并进已有 AGENTS.md 的短入口

本项目的上下文导航是 PROJECT_CONTEXT.md 和 CURRENT_TASK.md。恢复项目或继续任务时，先读这两个文件，再按当前任务核验关联源码；摘要不替代源码证据。阶段完成后更新摘要，保留当前需求、证据和下一步。

合并前阅读已有 AGENTS.md，不覆盖原有规则。若存在 AGENTS.override.md，应确认真正生效的入口。
