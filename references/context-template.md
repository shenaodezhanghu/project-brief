# 放到目标项目根目录的两个文件

以下为空白表单，不代表任何项目的已确认事实。初始化时要根据项目证据填写适用栏目；复杂项目保留足够细节，让没有当前会话历史的新模型只读这两个文件就能理解项目是什么、由什么构成、当前做到哪里以及下一步如何进入。未知项明确标注“待确认”或“待验证”，不要用空泛句子代替事实。

## PROJECT_CONTEXT.md

- 摘要格式：`project-brief-detailed-v2`；标记仅表示采用此组织方式，不代表事实已完整或已核验。
- 项目身份：项目名称、绝对根目录、Git 仓库状态、目标用户/使用者、解决的问题、整体目标；区分项目资料推断和用户确认。
- 项目工作范围：研究/产品主线、当前阶段的工作边界、明确不在本阶段处理的范围；历史排除项只记录会影响当前决策的索引，不在每次进度中重复展开。
- 用户长期偏好：只写已经明确确认、且会影响后续方案、命令、目录、输出或审批方式的偏好。
- 技术和运行：语言、框架、环境、固定解释器/工具路径、实际入口、运行命令、验证命令、输出目录和稳定资源要求；每项注明“已执行/仅文档/待验证”。磁盘剩余空间、最近测试数等实时数值放 CURRENT_TASK.md，并标注测量时间。
- 整体构成：从输入、数据处理、核心模块、训练/构建、推理/运行到输出的基本链路；对科研项目记录数据流、模型流和评价流。
- 模块索引：模块职责 → 完整项目相对路径/关键符号或路线文档 → 输入输出 → 何种任务需要读取 → 当前状态。按处理链路写明各环节是已选方向、待冻结参数、已实现接口、已验证能力还是尚未实现；一个环节可同时有已实现接口和待冻结参数。
- 数据与产物：数据来源、格式、划分/隔离规则、类别或场景范围、缓存/模型/结果目录、可复用与不可复用的产物、清理和删除约束。
- 关键约束和已定方案：用户确认的结论、理由、来源路径、适用范围、生效日期；分别标注已选方向、待冻结参数、已实现能力、已验证结果、provisional 指标和待批准动作。历史方案只保留仍影响当前决策的结论及证据索引。
- 当前方案索引：当前采用的方案/路线文件、版本或日期、已实现部分、未实现部分、替代旧方案的关系。
- 证据索引：README、路线文件、配置、入口代码、测试、实验记录和状态文档的完整项目相对路径；说明哪类任务需要读取哪份证据，避免规定每次读取全部资料。摘要不复制长文档。
- 摘要核验：生成/更新时间、本次核验的关键文件、仍未核验的区域；Git HEAD 和工作树现场等易变信息放 CURRENT_TASK.md，引用时注明时间。

## CURRENT_TASK.md

- 任务 ID / 状态 / 更新时间 / 当前工作目录、分支、Git HEAD（如有）及核验时间。
- 用户原始需求：简明保留范围、边界和授权；标明已确认与待确认。
- 验收标准：用户能观察到的完成结果和验证方法。
- 当前问题（可选，仅实际出现后填写）：触发条件、预期、实际、影响范围、证据路径。无问题时省略，不作为初始化必答项。
- 已完成：实际改动、产物路径、执行的命令和验证结果。
- 进行中：当前正在处理的入口、任务归属、已开始但未完成的动作。
- 待验证假设/阻塞：不要混入事实，写清验证方法和所需决定。
- 下一步：具体入口、前置条件和动作；不把历史待办自动当作授权。
- 工作现场：未提交文件、数据/模型状态、运行任务、最近测试结果与核验时间、磁盘剩余空间等有时效的资源数值、尚未处理的风险或阻塞。过期数值不得当作当前值使用。
- 交接状态（仅需要时）：交接 ID、来源/目标任务、节点 ID、接手第一步、验收方式和当前状态。

## 项目规则入口

使用本 Skill 目录下的 `scripts/install_project_contract.py` 安装项目根生效规则文件的自动维护受管区块，不手工复制旧版短入口。项目根存在 `AGENTS.override.md` 时写入该文件，否则写入 `AGENTS.md`。脚本只管理标记之间的内容，项目原有规则必须保留；更深层规则仍按其作用域执行。
