# Project Brief 维护成本测试指令

这套测试使用同一个项目、同一个模型和同一个推理等级。先完成全部无 Skill 会话，再开始有 Skill 会话，避免无 Skill 会话看到 Skill 生成的摘要。

把本目录中的 `PROJECT_CONTEXT_PROBE.md` 复制到被测项目根目录时，文件名保持不变。不要修改文件内容，也不要在测试会话中执行开发任务。

## 每个会话都要回答的共同要求

```text
请只理解当前项目，不修改任何文件，也不要执行开发任务。完成后请简要说明：
1. 这个项目是做什么的、解决什么问题；
2. 项目的整体构成；
3. 主要模块及各自职责；
4. 关键入口和基本运行链路；
5. 项目根目录是否存在 PROJECT_CONTEXT_PROBE.md。若存在，请说明测试标记、用途、构成、入口状态，并明确它是已实现功能还是仅有说明的规划组件；若不存在，请明确回答“未发现 Project Context Probe”。
无法从项目证据确认的内容标记为“待验证”。
```

## A 组：无 Skill，共 3 个新会话

### A1：初始项目

确认被测项目根目录不存在 `PROJECT_CONTEXT_PROBE.md`，然后创建第 1 个新会话并输入：

```text
本会话不要使用 project-brief Skill。

请只理解当前项目，不修改任何文件，也不要执行开发任务。完成后请简要说明：
1. 这个项目是做什么的、解决什么问题；
2. 项目的整体构成；
3. 主要模块及各自职责；
4. 关键入口和基本运行链路；
5. 项目根目录是否存在 PROJECT_CONTEXT_PROBE.md。若存在，请说明测试标记、用途、构成、入口状态，并明确它是已实现功能还是仅有说明的规划组件；若不存在，请明确回答“未发现 Project Context Probe”。
无法从项目证据确认的内容标记为“待验证”。
```

等待会话完全结束。

### A2：加入测试文件

把 `PROJECT_CONTEXT_PROBE.md` 复制到被测项目根目录，创建第 2 个新会话，输入与 A1 完全相同的指令，等待会话完全结束。

### A3：删除测试文件

删除被测项目根目录中的 `PROJECT_CONTEXT_PROBE.md`，创建第 3 个新会话，输入与 A1 完全相同的指令，等待会话完全结束。

## B 组：有 Skill，共 3 个新会话

开始前确认被测项目根目录不存在 `PROJECT_CONTEXT_PROBE.md`。

### B1：初始化并理解项目

创建第 1 个新会话并输入：

```text
$project-brief 初始化。

本次初始化目标：为后续新会话建立准确、精简的项目上下文。
验收标准：新会话能够说明项目用途、整体构成、主要模块职责、关键入口和基本运行链路，并能根据当前项目证据判断 PROJECT_CONTEXT_PROBE.md 是否存在。不要执行其他开发工作。

初始化完成后，请简要说明：
1. 这个项目是做什么的、解决什么问题；
2. 项目的整体构成；
3. 主要模块及各自职责；
4. 关键入口和基本运行链路；
5. 项目根目录是否存在 PROJECT_CONTEXT_PROBE.md。若存在，请说明测试标记、用途、构成、入口状态，并明确它是已实现功能还是仅有说明的规划组件；若不存在，请明确回答“未发现 Project Context Probe”。
无法从项目证据确认的内容标记为“待验证”。
```

如果技能仍提出初始化问题，按真实项目情况回答；等初始化和汇报全部结束后再进行下一步。

### M1：加入文件后立即维护

把 `PROJECT_CONTEXT_PROBE.md` 复制到被测项目根目录，立即创建一个维护会话并输入：

```text
$project-brief 维护，项目根目录刚加入 PROJECT_CONTEXT_PROBE.md。请核验文件和当前摘要，只维护项目上下文，不执行开发工作。
```

等待维护完全结束。这个会话记为 M1。

### B2：维护后的新会话恢复

维护完成后再创建第 2 个恢复会话并输入：

```text
$project-brief 继续。恢复完成后，请简要说明：
1. 这个项目是做什么的、解决什么问题；
2. 项目的整体构成；
3. 主要模块及各自职责；
4. 关键入口和基本运行链路；
5. 项目根目录是否存在 PROJECT_CONTEXT_PROBE.md。若存在，请说明测试标记、用途、构成、入口状态，并明确它是已实现功能还是仅有说明的规划组件；若不存在，请明确回答“未发现 Project Context Probe”。
无法从项目证据确认的内容标记为“待验证”。
```

等待恢复和汇报全部结束。

### M2：删除文件后立即维护

删除被测项目根目录中的 `PROJECT_CONTEXT_PROBE.md`，立即创建一个维护会话并输入：

```text
$project-brief 维护，PROJECT_CONTEXT_PROBE.md 已删除。请核验文件和当前摘要，清理已经失效的相关记录，不执行开发工作。
```

等待维护完全结束。这个会话记为 M2。

### B3：维护后的新会话恢复

维护完成后再创建第 3 个恢复会话，输入与 B2 完全相同的指令，等待恢复和汇报全部结束。

## 在前端选择会话

刷新 Token Observer：

- “无 Skill 会话”依次选择 A1、A2、A3。
- “有 Skill 会话”点击两次“添加会话”，依次选择 B1、M1、B2、M2、B3。
- 第 1 个 Skill 点是初始化；第 2、4 个点是维护；第 3、5 个点是新会话恢复。
- 先看“每次会话”，再切换到“累计成本”。

两组会话数量不同属于正常情况：无 Skill 生命周期有 3 次重新理解，有 Skill 生命周期包含 1 次初始化、2 次维护和 2 次恢复。此时以前端两个“累计”数值比较完整生命周期成本；“累计差异”会显示待配对。

结果有效时，A1/B1 和 A3/B3 都应回答未发现 Probe；A2/B2 应发现 `PB-CONTEXT-PROBE-V1`，并准确说明它只有规划说明、没有可运行入口。若回答不符合这些事实，即使 token 更少也不能视为更好。
